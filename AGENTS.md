# T1D Open Desk deployment handoff

- This is the native Cloudflare project on Nick's Mac mini. Read START-HERE.md, README.md, and this file before making changes. Use Cloudflare's standalone `cf` CLI, not `wrangler deploy`. The `wrangler.config.ts` file configures the local bundler that `cf` invokes; the two JSONC files are fallback references.
- Use Node to rebuild, syntax check, and run tests: `node build-native.mjs ./frontend`, `node --check bundle/index.mjs`, `npm test`. The installed Homebrew cf was v1.0.0-beta.13 at handoff; this project pins cf 1.0.0-rc.1 and its compatible bundler. If dependency installation is approved and needed, use `npm ci` when a package-lock.json exists, otherwise `npm install`; confirm local `npx --no-install cf --version` before using it. Validate with `npx --no-install cf deploy --dry-run --no-provision`. The dry run does not upload or need credentials.
- Nick's absolute ceiling is $200/month even under viral load. Do not deploy or provision anything until you have positively confirmed that the intended Cloudflare account has Workers Free and that all project resources remain within free-only limits, preferably in an isolated Free account. Never select Paid, upgrade, enable metered add-ons, or downgrade an account that has other workloads just for this project. If cf cannot read actual billing-plan state with the existing scoped session, securely verify Workers Free in the authenticated Cloudflare Billing dashboard or with a separately authorized, scoped read-only API. Account-list access is not proof of billing plan. Do not ask Nick to paste tokens into chat or log them.
- Default deployment is read-only with no D1, model calls, cron, or paid failover. Cloudflare Free quotas may return temporary failures rather than incur overages. The Workers Paid spending threshold is not an exact ceiling and does not include separately billed services such as D1. Do not swap to Paid to avoid quota exhaustion. Keep `--no-provision` on any later authorized deployment. Invite mode can only bind an already verified Free D1 ID; don't enable or migrate it without authorization. Keep secrets out of Git, public assets, URLs, and chat.
- Public access is for reading moderated evidence. Contributors bring their own compute and can submit public-evidence questions/findings/challenges for human review only once invite mode and credentials are approved. No auto-publishing; no health records, clinical advice, laboratory protocols or bioengineering. Research drafts are outside the public directory and must stay there.

Agents may fork the public source and open pull requests for their use cases. Follow CONTRIBUTING.md: no secrets, no health records or clinical advice, keep the default read-only, and wait for human review. There is no auto-merge. If a ~$200 spend alert arrives, use KILL-SWITCH.md, then reassess the plan.
